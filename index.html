1. Introdução à Linguagem C (Aula 9)

Fluxo de compilação · Características · Tipos primitivos · Operadores · Estruturas de decisão e repetição

Por que C em Alto Desempenho? C é uma linguagem de nível intermediário: combina legibilidade de alto nível com controle direto de hardware e memória. É usada em Sistemas Operacionais (Linux, Windows, Unix), drivers, sistemas embarcados (Arduino), compiladores (GCC), bancos de dados (MySQL) e jogos.
⚙️ Fluxo de Compilação em C & Comando GCC

Pipeline de Build: Código Fonte (.c) → Pré-processador (Código Pré-processado) → Compilador (Assembly) → Montador / Assembler (Código Objeto .o) → LinkEditor (Executável .exe).

gcc hello.c -o hello -Wall -Wextra
# -o     : define o nome do executável de saída
# -Wall  : ativa avisos principais do compilador
# -Wextra: ativa avisos adicionais (boas práticas)

Características do C: Compilada · Portável · Alta eficiência/desempenho · Acesso de baixo nível · Estruturada e procedural · Tipagem estática · Case-Sensitive (idade ≠ Idade).

📚 Bibliotecas Padrão & Tipos Primitivos

Principais Diretivas #include

  • #include <stdio.h> — Entrada e saída (printf, scanf, puts, gets)
  • #include <stdlib.h> — Funções padrão e memória (malloc, free, exit)
  • #include <math.h> — Funções matemáticas (sqrt, pow, etc.)
  • #include <string.h> — Manipulação de strings (strcpy, strcat, strlen, strcmp)

Dicas: Sempre encerrar comandos com ; · Salvar e recompilar após cada edição · Comentários: // linha ou /* bloco */.

🔢 Operadores e Estruturas de Controle

Operadores

  • Aritméticos: +, -, *, / (divisão inteira entre ints), % (módulo/resto), ++, --
  • Relacionais: ==, !=, >, <, >=, <=
  • Lógicos: && (AND), || (OR), ! (NOT)

Decisão

  • Condicional Simples: if (cond) { ... }
  • Condicional Composto: if (cond) { ... } else { ... }
  • Condicional Seletivo: switch (var) { case X: ... break; default: ... } (ideal para múltipla escolha)

Repetição (Laços)

  • while (Pré-teste): Testa a condição antes de executar; pode rodar 0 vezes.
  • do...while (Pós-teste): Testa no final; garante pelo menos 1 execução.
  • for (Determinado): 3 partes — início, condição de parada e incremento.

2. Estruturas de Dados, Strings, Funções e Ponteiros (Aula 10)

Vetores e matrizes · Strings terminadas em '\0' · Passagem por valor vs. ponteiro · Stack vs. Heap (malloc/free)

📦 Estruturas de Dados, Vetores e Matrizes

Classificação & Vetores (Arrays)

  • Lineares: Vetores/Matrizes, Listas encadeadas, Pilhas, Filas.
  • Não Lineares: Árvores e Grafos.
  • Vetor: Conjunto de elementos consecutivos em memória, todos do mesmo tipo, acessados por índice a partir de um único nome. Cuidado: C não bloqueia acesso fora dos limites do vetor!

Matrizes Multidimensionais

Vetores de 2 ou mais dimensões (sem limite teórico de dimensões):

float Notas[Prova][Aluno];        // 2D
float Notas[Turma][Prova][Aluno]; // 3D
🔤 Strings em C e Biblioteca <string.h>
C não possui um tipo nativo string! Uma string é um vetor de char terminado pelo caractere nulo '\0'. Por isso: 'a' (aspas simples = 1 char) ≠ "a" (aspas duplas = {'a', '\0'}). Sempre reserve +1 posição para o '\0'!

Leitura e Escrita de Strings

  • scanf("%s", nome) — NÃO usa &; para ao encontrar espaço, tab ou Enter.
  • printf("%s", nome) — Imprime até encontrar '\0'.
  • gets(nome) — Lê várias palavras com espaços.
  • puts(nome) — Imprime a string e quebra a linha automaticamente.

Funções de <string.h>

  • strcpy(dest, orig) — Copia a string de origem para destino.
  • strcat(dest, orig) — Concatena origem ao final do destino (cuidado com tamanho!).
  • strlen(str) — Retorna a quantidade de caracteres válidos (sem contar '\0').
  • strcmp(s1, s2) — Compara via tabela ASCII: 0 (iguais), > 0 (s1 maior), < 0 (s1 menor).
🎯 Funções, Ponteiros e Alocação Dinâmica (Stack vs. Heap)

Funções: Argumentos e Retorno

  • Pode ter múltiplos argumentos, mas retorna apenas um único valor (ou void). A função main() retorna int (0 = sucesso; outro valor = erro).
  • Tipos primitivos: Passagem por cópia (valor) — alterar dentro da função não muda a variável original.
  • Vetores e Matrizes: Passam um ponteiro para a primeira posição — alterar dentro da função modifica o original!

Ponteiros: * e &

Ponteiros são variáveis que armazenam endereços de memória (podem iniciar com NULL).

  • int *p; — Declara ponteiro para inteiro.
  • &var — Operador de endereço (obtém onde var está na memória).
  • *p — Operador de desreferência (acessa o valor guardado no endereço apontado).
int idade = 28;
int *p = &idade; // p guarda o endereço de idade
printf("%d", *p); // imprime 28

3. Introdução à OpenMP, Concorrência e Lei de Amdahl (Aula 11)

Limites do paralelismo · Sintaxe e compilação OpenMP · Processos vs. Multithreads · Modelo Fork-Join

📈 Lei de Amdahl (Limite Teórico do Speedup)
Princípio: Nem toda tarefa é paralelizável (ex: 2 fornos não assam 1 bolo na metade do tempo, mas assam 10 bolos mais rápido). A Lei de Amdahl demonstra que o ganho máximo de velocidade (Speedup) é estritamente limitado pela fração sequencial do programa!
Speedup(n) = 1 / [ s + (1 − s) / n ]

Onde: s = fração estritamente sequencial · 1 − s = fração paralelizável · n = número de processadores/núcleos.

Exemplo da Aula: Se 95% de um programa é paralelizável, então s = 0,05 (5%). Mesmo com infinitos núcleos (n → ∞), o ganho máximo teórico é: 1 / 0,05 = 20× mais rápido.

🛠️ OpenMP (Open Multi-Processing): Sintaxe e Compilação

Diretivas e Compilação

API de memória compartilhada para C, C++ e Fortran baseada em diretivas de compilador (#pragma) e biblioteca <omp.h>.

// Compilação obrigatória com -fopenmp:
gcc -fopenmp codigo.c -o saida
.\saida.exe
#include <omp.h>
#include <stdio.h>

int main() {
  #pragma omp parallel num_threads(4)
  {
    int id = omp_get_thread_num();
    printf("Ola da thread %d\n", id);
  }
  return 0;
}

Funções Essenciais e Modelo Fork-Join

  • omp_get_thread_num() — Retorna o ID inteiro da thread atual (0 é a Master), muito usado para dividir tarefas.
  • omp_set_num_threads(N) — Define o número de threads criadas (ou usar a cláusula num_threads(N) direto no #pragma).
Modelo Fork-Join: O programa inicia sequencialmente na Thread Master (ID 0). Ao atingir #pragma omp parallel ocorre o Fork (cria/despacha um time de threads que executam o mesmo bloco). Ao final do bloco há uma barreira implícita (Join): todas aguardam as demais terminarem antes de retomar a execução sequencial.

4. Falso Compartilhamento e Sincronização (Aulas 12 e 13)

Memória Cache e False Sharing · Critical, Atomic, Barrier · Single, Master, Nowait · Sections

💥 Falso Compartilhamento (False Sharing) — Por que o Paralelo Ficou Mais Lento?
O Problema na Série Harmônica (V1): Ao criar um vetor compartilhado double soma[4] onde cada thread escreve apenas em soma[id], parece não haver conflito. Porém, uma linha de cache típica tem 64 bytes (cabem 8 double de 8 bytes!). Como soma[0..3] ficam na mesma linha de cache, toda vez que a Thread 0 atualiza soma[0], o hardware precisa invalidar e sincronizar a linha inteira nos caches dos outros núcleos — destruindo o desempenho!

Solução Didática V2: Padding em Matriz

Usar uma matriz double soma[NUM_THREADS][8] (8 colunas × 8 bytes = 64 bytes por linha), acessando apenas soma[id][0]. Cada thread isola-se em sua própria linha de cache.

Limitação: Prova o efeito da cache e acelera o código, mas desperdiça memória.

Solução V3: Variável Local + critical Fora do Laço

Cada thread acumula em uma variável local (na Stack) durante todo o for, e só entra na região #pragma omp critical uma única vez ao final para somar na variável global!

Regra de Ouro: Nunca coloque critical dentro de um laço com milhões de iterações — o custo de sincronização serializa o programa.

🔀 Paralelização Sem Laços: sections e section

Permite atribuir blocos estruturados / funções diferentes para serem executados em paralelo por threads distintas (paralelismo funcional). Possui barreira implícita ao final de sections.

#pragma omp parallel
{
  #pragma omp sections
  {
    #pragma omp section
    { tarefa_A(); }

    #pragma omp section
    { tarefa_B(); }
  } // Barreira implícita aqui (a menos que use nowait)
}

5. Laços Paralelos, Redução e Escalonamento (Aula 14)

omp for · Independência de iterações · collapse(n) · reduction · Políticas de schedule

🔁 Diretiva #pragma omp for e parallel for

Regras Fundamentais

  • Instrui o compilador a dividir automaticamente as iterações do for entre as threads da equipe.
  • Forma compacta: #pragma omp parallel for (quando o laço é o único comando da região paralela).
  • Restrição: O índice do omp for não aceita tipo double (apenas inteiros/ponteiros).
  • A variável de controle i é privada por padrão (pode ser declarada explicitamente com private(i)).

Independência & Laços Aninhados (collapse)

  • Independência obrigatória: Uma iteração não pode depender do valor calculado na iteração anterior (ex: j acumulado). Solução: tornar j privado e recalculá-lo em função direta de i.
  • collapse(n): Para laços aninhados sem dependência (especialmente com desbalanceamento no laço interno), achata n laços em um único espaço de tamanho N * M e distribui entre as threads.
➕ Redução (reduction) — A Forma Mais Limpa de Acumular
Como funciona reduction(op : lista): Cria automaticamente uma cópia privada da variável em cada thread, inicializada com o elemento neutro da operação (ex: 0 para +, 1 para *). Ao final do laço, combina todas as cópias parciais na variável global sem condição de corrida e sem falso compartilhamento!

Operadores Suportados em C/C++

+ - * max min & (AND bit) | (OR bit) ^ (XOR bit) && ||

Série Harmônica — Versão V5 Simplificada

double soma = 0.0;
#pragma omp parallel for reduction(+:soma)
for (long long i = 1; i <= 1000000000; i++) {
    soma += 1.0 / i;
}

6. OpenMP Tasks, Compartilhamento de Dados e SIMD (Aula 15)

Tarefas assíncronas e recursão · shared, private, firstprivate, lastprivate · Vetorização SIMD

📋 OpenMP Tasks (#pragma omp task e taskwait)

Conceito e Padrão de Criação

  • Tasks são unidades de trabalho independentes executadas dinamicamente (imediatamente ou atrasadas) por qualquer thread livre da equipe. Ideais para recursão, árvores e listas encadeadas.
  • Normalmente criadas dentro de #pragma omp parallel + #pragma omp single (uma thread gera as tarefas e as demais executam).
  • Sem barreira automática: Use #pragma omp taskwait para esperar todas as tasks filhas concluírem antes de usar seus resultados!

Exemplo Clássico: Fibonacci Recursivo

int fib(int n) {
  int x, y;
  if (n < 2) return n;
  #pragma omp task shared(x) firstprivate(n)
  x = fib(n - 1);
  #pragma omp task shared(y) firstprivate(n)
  y = fib(n - 2);
  #pragma omp taskwait // Aguarda x e y ficarem prontos
  return x + y;
}
// Chamada na main:
#pragma omp parallel
#pragma omp single
res = fib(30);

🚀 Instruções SIMD (Single Instruction, Multiple Data)
Vetorização em Hardware: Diferente do modelo escalar SISD (1 instrução sobre 1 dado), processadores modernos possuem unidades vetoriais SIMD que aplicam uma única instrução simultaneamente sobre 2, 4, 8 ou mais elementos independentes (ex: soma de vetores C[i] = A[i] + B[i]).

Diretiva #pragma omp simd

Garante ao compilador que as iterações não têm dependência e podem ser vetorizadas em registradores SIMD:

#pragma omp simd
for (int i = 0; i < N; i++) {
    C[i] = A[i] + B[i];
}

Combinando Threads + Vetorização + Collapse

É possível combinar paralelismo multicore (parallel for), achatamento de laços (collapse) e vetorização (simd):

#pragma omp parallel for simd collapse(2)
for (int i = 0; i < N; i++)
  for (int j = 0; j < M; j++)
    C[i][j] = A[i][j] + B[i][j];
